# VAR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Contestar pontos do outro; o ponto só cai se o contestado aceitar.

**Architecture:** Tabelas `var_lances` e `var_mensagens` com RLS que garante as transições. Pontos anulados entram como parâmetro opcional da pontuação existente. UI em `src/components/Var.tsx`, ligada a Histórico, Hoje e Ranking.

**Tech Stack:** React 18 + TS, Supabase (Postgres/RLS), Vitest + Testing Library, PGlite.

**Spec:** `docs/superpowers/specs/2026-11-10-var-design.md`

## Global Constraints

- Pontos: `'cafe' | 'almoco' | 'jantar' | 'atividade' | 'agua'`. Estados: `'aberto' | 'aceito' | 'retirado'`.
- Motivo 3–300 caracteres; mensagem 1–300.
- Ponto em lance aberto continua valendo; só `aceito` anula.
- Todo teste de página com `vi.mock('../data/repo')` precisa mockar `getLances` (`[]`).

## Review Focus

1. Contestado tenta retirar / autor tenta aceitar → banco recusa (teste RLS, Task 1).
2. Aceitar dois lances do mesmo dia desconta os dois pontos, nunca abaixo de 0 (Task 2).
3. Lance aceito de um dia fora da janela do ranking (semana) não desconta da semana (Task 2).
4. Abrir VAR em ponto que deixou de existir (pessoa desmarcou) → banco recusa e a tela avisa (Tasks 1 e 4).
5. Folha aberta enquanto o outro decide → ação falha, toast e recarrega (Task 4).
